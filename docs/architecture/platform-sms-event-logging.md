# Cross-system SMS audit in Platform

`platform.sms_logs` now records `SourceSystem` (`platform`, `schools`, `family`), `MessageTypeCode` (for example `otp`, `notification`, `other`), nullable `SchoolId`, and nullable `SourceMessageId` in addition to the encrypted recipient/message/provider response and delivery outcome. Existing Platform rows are backfilled as `platform` / `otp` by `AddSmsLogSourceMetadata`. New Platform sends supply an explicit message type; first-owner activation uses `otp`.

Schools and Family will publish `SmsDeliveryAttemptRecordedV1` after their own SMS attempt completes. Use `IntegrationMessageEnvelope<T>` with a **stable** `messageId` for the source attempt, `producer` equal to `schools` or `family`, and the relevant `scope`. School messages require `tenantId` and `schoolId` to be the same non-empty GUID; Family may use global or school scope. The data contains `messageTypeCode`, recipient, exact message text, raw gateway response (nullable when none was received), HTTP status, `Accepted` / `Rejected` / `Failed`, sanitized failure reason, and attempt/completion UTC timestamps. Never invent a new message ID when retrying publication of the same attempt.

The Platform Worker consumes from durable topic exchange `mdaresna.sms-audit`, routing keys `sms.delivery.schools` and `sms.delivery.family`, queue `platform.sms-log.v1`. It checks that routing key and envelope producer agree, deserializes the versioned contract, and stores the log plus `messaging.inbox_messages` receipt in one transaction. It acknowledges RabbitMQ only after commit; a redelivery with the same message ID is ignored. Invalid events go to `platform.sms-log.v1.dead`, whose payloads expire after one hour. Transient persistence failures are requeued after a short delay. The direct Platform SMS sender writes its own log and does not publish a duplicate event.

The consumer is **off by default** because Schools/Family producers and the deployment broker are not in place. To enable it, set `SmsLogConsumer__Enabled=true` and supply `SmsLogConsumer__BrokerUri` as an `amqps://` URI through a secret store. The Worker also needs the same stable `PlatformSms__EncryptionKey` used by the Platform API. Do not commit these secrets. Publish persistent messages from each source's transactional outbox, use publisher confirms and mandatory routing, and grant each producer permission only for its own routing key. The queue contains sensitive plaintext SMS text until it is consumed; require TLS, broker-at-rest protection, restricted broker/DLQ access, and an operational retention policy. Never write event bodies, gateway responses, broker URI, or OTPs to ordinary logs.

No Schools or Family backend project exists yet, so there is no producer implementation in this repository and no live end-to-end broker run. The contract, Platform consumer, and persistence integration are testable now; cross-system delivery must still be validated against an actual secured RabbitMQ deployment when those apps are built.
