# تشفير الملفات والنسخ الرقمية لإصدارات الكتب

## الحالة والنطاق

الكود يشفّر كل رفع جديد في Document Core المدرسي (صور المدرسة والشعار والمنشورات والخطط والواجبات والأنشطة والملاحظات والكتب)، وصور الحسابات المدرسية وPlatform المخزنة داخل قاعدة البيانات. لم يتم نشر هذه الدفعة أو تشفير بيانات فعلية. الملفات السابقة تبقى قابلة للقراءة مؤقتًا وتحتاج ترحيلًا صريحًا؛ النسخ الاحتياطية القديمة وأي ملفات خارج هذه التطبيقات ليست مشفرة تلقائيًا.

## المفاتيح — شرط تشغيل الرفع

- `UploadEncryption:ActiveKeyId`: معرف المفتاح النشط، أحرف ASCII وأرقام وشرطة، حتى 64 حرفًا.
- `UploadEncryption:Keys:{keyId}`: مفتاح عشوائي 256-bit بترميز Base64 من secret manager أو متغيرات البيئة. لا تستخدم كلمة مرور أو قيمة افتراضية أو تحفظ المفتاح بالمستودع/الـlogs. للتطوير فقط يمكن استخدام user-secrets.
- Docker يستخدم `PLATFORM_UPLOAD_ENCRYPTION_KEY` و`SCHOOLS_UPLOAD_ENCRYPTION_KEY` مصدرهما مخزن الأسرار؛ لا يُسجل أي محتوى لهما هنا. مفاتيح مستقلة لكل بيئة؛ يجب أن تتطابق بين replicas التابعة للخدمة نفسها.
- عند التدوير أضف مفتاحًا جديدًا وغيّر ActiveKeyId واحتفظ بالقديم حتى ترحيل كل محتواه ونسخه الاحتياطية. حذف مفتاح مستخدم يفقد القدرة على القراءة، ولا يوجد fallback للمحتوى المشفر.
- أعد تشغيل/نشر replicas عند تغيير key ring؛ مخزن Document Core يحمل إعداد التشفير عند إنشائه ولا يفترض hot reload للمفاتيح.
- احتفظ بنسخة مفاتيح آمنة منفصلة عن backup الملفات وقاعدة البيانات؛ اختبر الاستعادة. فقد المفتاح يعني فقد الملفات.

## صيغة التخزين

غلاف `MDAENC01` بإصدار محدد، ومعرف المفتاح وsalt عشوائي 256-bit وطول plaintext موثّق. HKDF-SHA256 يشتق مفتاح AES-256-GCM مستقلًا لكل ملف وسياق. أجزاء 64KiB بتوقيع GCM مستقل وnonce تسلسلي؛ الرأس موثّق كذلك. يرتبط التشفير بمسار التخزين أو هوية الحساب/المدرسة لمنع نقل ciphertext بين المالكين. تدعم القراءة Seek/Range دون فك الملف كله؛ البصمة والحجم metadata يظلان للملف الأصلي. الملفات الجديدة filesystem تحمل `.enc`؛ لا يُكشف مسار عام ولا يُرسل مفتاح للعميل.

غلاف صور الحسابات نفسه داخل عمود Content، فلا يحتاج تغيير أعمدة الصورة. الملف يُفك في الذاكرة بعد التحقق من الوصول. التلف أو المفتاح المفقود يفشل القراءة ولا يعيد bytes مشفرة أو plaintext بديلة. ملفات ciphertext المؤقتة/الفاشلة تنظّف بأفضل جهد.

## استقبال الملفات والاستضافة

- multipart يبقى في الذاكرة: threshold 64MiB وbody limit 54MiB لتجنب نسخ plaintext المؤقتة من model binding للملفات المدعومة. حدود المحتوى الحالية لكل وحدة مستقلة؛ الكتب PDF حتى 50MiB و1–2000 صفحة بلا password.
- استخدم HTTPS وبروكسي لا يحفظ أجسام الرفع على القرص: مثل `proxy_request_buffering off` في Nginx. لا body logging. راجع WAF/بروكسي/مراقبة/تخزين crash dumps وswap: التشفير في التطبيق لا يغطي نسخًا تنشئها البنية الخارجية. تشفير volumes/backup/swap أو تعطيله جزء مستقل من إعداد الاستضافة.
- حدّد عدد طلبات الرفع والتصيير والذاكرة على مستوى gateway/container لمنع استنزاف RAM. لا تغيّر upload limits قبل مراجعة حد multipart ومساره.
- قارئ الكتاب يستخدم `pdfinfo` و`pdftoppm` من Poppler؛ أضيف poppler-utils إلى Docker Schools API. يمكن تحديد executable موثوق من `BookDocuments:PdfInfoPath` و`BookDocuments:PdfToPpmPath`. لا مسار يأتي من المستخدم، ولا shell، ولا ملفات PDF مؤقتة يكتبها التطبيق؛ stdin/stdout فقط. شغّل runtime محدثًا كمستخدم غير root مع تقييد الشبكة والموارد/sandbox للـrenderer. مهلة 30 ثانية وحد مخرجات وعمليتان متوازيتان لكل replica.
- فحص الترويسة والتصيير لا يساوي antivirus. حالة Document Validation تظل Pending؛ فحص malware العميق باقٍ.

## ترحيل الملفات السابقة

1. خذ backup متسق للـDB والـvolume، وأوقف الرفع والكتابة والـjobs أثناء الصيانة. جهز المفاتيح وتأكد من قدرة القراءة والاستعادة؛ لا تنفذ ترحيلًا أثناء حركة كتابة متزامنة.
2. لكل مدرسة: مدير لديه `school.academics.manage` و`school.profile.manage` يستدعي POST `/api/schools/v1/uploads/encryption/migrate?profileOffset=0` بمصادقة المدرسة.
3. كل دفعة ترحّل حتى 16 نسخة مستند بما فيها التاريخية/المحذوفة/المرفوضة، وتتحقق من SHA256 والحجم ثم تحفظ storage key الجديد وتزيل الأصل بعد نجاح DB. ترحّل حتى 16 صورة حساب كذلك. كرر مع nextProfileOffset حتى profilesComplete، ثم بنفس آخر offset حتى remainingDocuments=0. عدد المستندات منفصل عن cursor الصور.
4. Platform: صلاحية `platform.access.manage` تستدعي POST `/api/platform/v1/uploads/encryption/migrate?offset=0` ثم nextOffset حتى complete، لتشفير صور Identity.
5. بعد اكتمال الدفعات افحص الـvolume بحثًا عن plaintext متبقية من انقطاع بعد commit وقبل حذف الأصل. لا تعتبر العداد صفر إثباتًا لخلو الـvolume أو النسخ الاحتياطية من plaintext. الأصل المفقود أو اختلاف hash يوقف الدفعة ولا يُتجاهل. crash قبل تحديث DB قد يترك `.enc` يتيمًا ويحتاج فحصًا واستعادة maintenance قبل retry؛ لا تحذف غير المراجع تلقائيًا.
6. اختبر صور الحسابات والشعار والمنشور والخطط والمرفقات وRange الفيديو، ثم خذ backup مشفرًا جديدًا قبل إعادة التشغيل. تعالج backups السابقة بسياسة احتفاظ وتشفير منفصلة؛ لا تمحها آليًا.
7. بعد مراجعة اكتمال الترحيل اضبط `UploadEncryption:AllowLegacyRead=false` في الخدمتين لمنع قراءة plaintext السابقة؛ الافتراضي true أثناء فترة الانتقال فقط، ولا يسمح بكتابة plaintext جديدة.

## نسخة إصدار الكتاب

- طبّق PostgreSQL `20261013223025_AddBookVersionDigitalDocuments` أو SQL Server `20261013223149_AddBookVersionDigitalDocuments` من تحديث المدارس المركزي بعد backup، ولا تشغل migrations تلقائيًا عند بدء API.
- الإعدادات الأكاديمية ← المواد والمناهج والكتب ← إصدارات الكتب ← النسخة الرقمية في Web/Flutter. للقراءة `school.academics.view` وللرفع/السياسة `school.academics.manage` داخل قاعدة المدرسة الحالية. القراءة مقيدة بكتاب وإصدار نشطين غير محذوفين؛ توسيع جمهور المدرسين/الأسرة عبر نطاقات المنهج عمل مستقل، ولا يمنحه flag المشاركة الآن.
- يرفع PDF ويربط بإصدار مستند typed، ويحتفظ بالمستند السابق عند الاستبدال للأثر التاريخي. يغيّر الملف أو السياسة باستخدام ExpectedRevision لمنع فقد تعديل متزامن. audit للرفع وتغيير السياسة وتنزيل الأصل؛ الصفحة مرتبطة بمستخدم/مدرسة/وقت كعلامة مائية معرفية، لا اسم الطالب أو الأسرة.
- sharing للأسرة إعداد مستقبلي فقط، ولا Family API/UI جديدة. AllowDownload مستقل ويُفحص في السيرفر؛ لا مسار عام للوصول للأصل أو تجاوز السياسة عبر query preview. قارئ الصفحات يتلقى PNG بعلامة مائية مرسومة على pixels في السيرفر، مع no-store/nosniff. HTML لا يتلقى PDF عند المنع، لكن صور الصفحات نفسها يمكن التقاطها؛ ليست DRM مطلقة.
- Android: FLAG_SECURE أثناء القارئ عندما يمنع تنزيل الأصل، ويزال عند مغادرته. iOS: رصد التقاط/تسجيل الشاشة وحجب المحتوى أثناءه، وليس منع screenshot مسبقًا؛ Web/desktop علامة مائية بلا وعد بمنع تصوير الشاشة. native iOS/Android يحتاج build وتجربة جهاز حقيقية قبل الإنتاج.

## تحقق قبل النشر

اختبارات ciphertext/tamper/scope/key rotation/Range وAPI policy؛ integration Poppler opt-in باستخدام `MDARESNA_TEST_POPPLER=1`. اختبر إعادة تشغيل replicas بالمفاتيح الصحيحة، مفتاحًا خاطئًا، استعادة backup، حسابًا دون صلاحية، مدرسة أخرى، تعديلًا متزامنًا وسحب التنزيل، PDF تالفًا/كبيرًا/password، reader timeout، تسجيل الشاشة على الأجهزة، وترحيل بيانات حقيقية على staging. نجاح unit tests لا يغني عن تلك التجارب.
